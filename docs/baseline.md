## 🔁 재현 명령 (PowerShell)

```powershell
# 1) 회귀 테스트 + 챕터 감지 정확도
npm test

# 2) 정적 디자인 지표 (의존성 없음)
node tests/measure-design.js

# 3) 런타임 지표 — 측정 도구는 앱 의존성이 아니므로 --no-save로 임시 설치
npm install --no-save playwright-core axe-core
node tests/measure-runtime.js --runs 5   # INP는 1회 값이 크게 흔들려 5회 중앙값으로 비교
node tests/measure-ia.js                 # 정보 구조: 보이는 조작 요소·Tab 횟수·문서 높이 (결정적, Phase 33)
node tests/measure-batch.js              # 일괄 변환: 파일 7개의 감지 상태를 알기까지 클릭·시간 (Phase 35)
node tests/measure-interval.js           # 간격 분할: 정답을 아는 합성 원고 30개로 경계 정확도 (Phase 40, 브라우저 불필요)

# 4) Lighthouse — 배포 사이트 기준 (실제 사용자 조건, 구글 폰트 포함)
npx lighthouse https://novel2epub.pages.dev/ --only-categories=performance,accessibility,best-practices --view
npx lighthouse https://novel2epub.pages.dev/ --preset=desktop --only-categories=performance,accessibility,best-practices --view

# 5) EPUBCheck — npm test가 만든 tests\out\*.epub 검사 (Java 17 필요)
Invoke-WebRequest https://github.com/w3c/epubcheck/releases/download/v5.1.0/epubcheck-5.1.0.zip -OutFile epubcheck.zip
Expand-Archive epubcheck.zip -DestinationPath . -Force
Get-ChildItem tests\out\*.epub | ForEach-Object { java -jar epubcheck-5.1.0\epubcheck.jar $_.FullName }
```

- **제목·작가** — 파일명 규칙은 그대로(`[작가] 제목` · `제목@작가`)이고, 제목에서 범위·완결·연재중·밑줄만 걷어 냄(`최강_신이라 … 1-868 연재중` → `최강 신이라 …`). 본제목 속 숫자 범위(`2-3반`·`18-19세기`)·괄호 부제(`(외전 포함)`)는 그대로, 글자가 다 지워지면 원래 값. 목록에서 제목·작가를 바로 고치고 변환은 고친 값 우선(제목을 비우면 기본값). ZIP 안에서 같은 이름은 `(2)`

## ✂️ 18. Phase 40 (간격 분할 v2) 결과

### 무엇을 바꿨나 (parser.js `_intervalFeatures` · `_intervalStartsDP` → `computeIntervalSplit`)
1. **글자 수 기준** — 화 위치를 줄 수가 아니라 누적 글자 수로 봄 (대사 위주 화는 줄이 많고 서술 위주 화는 적음)
2. **전체 최적화** — 후보 줄마다 점수를 매기고, '점수 합 − 화 길이 비용'이 가장 큰 경계 조합을 동적 계획법으로 고름. 화 개수는 경계마다 매기는 비용 λ를 이분 탐색해 맞추고, 남거나 모자라면 전체 점수 변화가 가장 작은 경계를 빼거나 가장 이득인 후보를 넣음. 화 길이 비용은 평균보다 긴 화에 무겁고 짧은 화(공지·작가의 말)에 가벼움
3. **파일 안에서 제목 찾기**
   - 번호 흐름: 짧은 숫자 줄을 번호 앞뒤 모양으로 묶어, 화수의 0.4~2.2배이고 앞 줄 번호 +1이 절반 이상이면 제목 가족. 경계끼리 번호가 +1이면 +160 (같으면 분할 화 +40, +2면 누락 +60, 그 밖 −60). 번호 없는 경계(공지·권)를 건너서도 흐름을 이어 봄
   - 반복 구분선(`◇◇◇` 등): 화수의 85~115%이고 간격이 고를 때(변동계수 0.6 이하)만 — 장면 전환 `***`은 제외
   - 되풀이되는 같은 줄: 화수만큼 고르게 나오면 파일 맨 앞 첫 등장은 머리줄(화 시작), 맨 끝 마지막 등장은 꼬리줄(다음 줄이 경계)
   - 빈 줄: 고정 점수 대신 이 파일에서 그 길이 이상 빈 곳이 경계 수의 몇 배인지로 (1.2배 이하 130 · 2.5배 90 · 5배 40)
   - 프롤로그·에필로그·외전·작가의 말·공지·N권 줄은 정규식 감지와 무관하게 제목
   - 제외: 같은 번호만 반복(본문 속 `1화` 언급) · 바로 위아래에 같은 모양(번호 목록·카운트다운, −80)
   - 정규식 감지 제목 줄은 화수의 85~115%일 때만 크게(+300) 믿고, 넘치거나 크게 모자라면 약하게
- 정규식 제목 줄 수가 화수와 정확히 맞으면 이전처럼 그 줄들(빠른 길). `opts.engine==='legacy'`나 v2 실패 시 이전 방식
